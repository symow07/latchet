# Latchet — Pre-Deployment Review

_29 August 2026 · verified against the working tree at `f195b16`, not against my own notes._

**Verdict: the committed code is shippable. Your working tree is not, and that is the finding.**

`main` at `f195b16` is a complete, roadmap-closed v1. Sitting on top of it, uncommitted, is a
visual redesign that is **14% done and currently makes most of the app unreadable**. Nothing is
lost and nothing is broken in git — but this is not a state to build from, and it is the single
thing standing between you and a submission.

38 changed files, 8 new ones, +2,702/−2,016 lines, uncommitted, last touched yesterday.

This is not stylistic drift — it is white-on-white text across two thirds of the app.

**What I could and couldn't verify:** `tsc --noEmit` passes clean on the working tree, so it
compiles. I could not run the test suites — they use `bun test` and this VM has Node but not Bun.
The last reported figures were 239 backend + 157 mobile.

### The decision you actually have to make

**Option A — stash the redesign, ship what's committed.** `f195b16` is coherent, complete, tested
and roadmap-closed. Branch the redesign, ship v1 in the dark theme it was designed in, land the new
look as 1.1 when all 44 screens are converted. This is what I'd do.

**Option B — finish the conversion first.** 38 screens, 91 literals. Real work, and it puts a
large, entirely-unverified visual change in front of a build you haven't yet been able to make.

**What you must not do is build from the tree as it stands.** A local Xcode build takes the working
directory, and that is how the 27 August build was produced.

## 2. What's genuinely finished — and where I was wrong

The roadmap is closed: **33 tasks complete, 0 open**, extended to Phase 10. Corrections to my own
earlier documents, which the agent made and I've now confirmed:

- **The app icon exists.** `mobile/assets/` holds `icon.png` (1024²), `adaptive-icon.png`,
  `splash-icon.png`, `favicon.png`, all declared in `app.json`. My checklist called this a hard
  blocker; it hasn't been one for two days.
- **Arabic shipped.** I recommended deferring it to v1.1. It's in, with RTL, and the six CLDR
  plural forms are implemented and tested. Four languages live.
- **Both pre-launch features are done** — household sharing and the personalised advisor, Phase 10.
- **`app.json` is materially better than I audited.** Android permissions trimmed to camera and
  biometrics; the phantom `RECORD_AUDIO` and storage permissions are gone, replaced by a proper
  `NSMicrophoneUsageDescription`. Four new config plugins (share extension, app intents, shortcut
  localisation, expo-audio).
- **The 27 August build was verified the hard way.** EAS was blocked (free-tier iOS builds
  exhausted until 1 September, and `preview` is a device profile with no Apple credentials), so the
  same artifact was built with Xcode in Release: 4,112 compile steps, an 11.7 MB production bundle,
  icons in `Assets.car`, share extension embedded, installed and launched with session persistence
  intact. That is most of what an EAS build would have told you.

Production is up — `{"status":"ok"}` from an independent network, and that endpoint runs a real
`SELECT 1`, so the database volume is genuinely reachable.

## 3. 🔴 The deployment is live but unusable

Unchanged, and now the longest-standing item on the list: **production has only
`BETTER_AUTH_SECRET` and `DATABASE_URL` set.**

- No email provider → `lib/email-otp.ts:67` throws → **nobody can sign in, including you.**
- No `OPENAI_API_KEY` → every AI route 503s → the advisor, receipt scan, email detection and PDF
  import are all dead, which is the entire tier RevenueCat exists to sell.
- The key in `backend/.env` is a **placeholder** shaped like a credential, ending in `r3al`. Every
  request with it returns 401.

You have a complete app in front of a door nobody can open. This is ten minutes of work and it has
been outstanding for over a week.

## 4. Needs adjustment before submission

**Every build that exists predates two fixes it needs.** The 26 August build (`00f35e33`) calls the
business backend with bare `fetch` and `credentials: 'include'`, which attaches nothing on this
stack — so every business screen requests logged out, 403s, and renders empty. That is your
"business profile doesn't work". Fixed in `5a1d2b4`, present in no build. Separately that build
reads `business.teamMembers`, renamed to `members`, now absorbed server-side by
`lib/legacy-aliases.ts`. **Neither reaches a phone without a new build.**

**The advisor's refusal behaviour has never met a live model.** `advisor-adversarial.test.ts` is
written and skips loudly without a key. The guardrails are enforced server-side and proven to reach
the model, but nothing proves the model *obeys*. Given you chose the health-data tier, run this
before shipping it — it is the one test that stands between a safety design and a safety claim.

**The production database file is named `dev.db`.** It's inside the Railway volume so nothing is at
risk, but renaming needs `DATABASE_URL` changed and the file moved in one window. Doing only the
first points production at an empty database. Either do it carefully or leave it — do not do it
casually.

**`support@latchet.app` still doesn't exist** (`(business-tabs)/settings.tsx:98` carries the <!-- TODO(domain) -->
TODO). Apple verifies the support address resolves. Blocked on the domain purchase.

**Arabic has never been read by a native speaker.** The grammar is structurally correct; the wording
isn't reviewed. Worth one pass from someone who reads it before those users see it.

**Gmail OAuth is dead code** — `getEmailAuthUrl`, `scanEmailSubscriptions`, `disconnectEmail`,
`saveEmailSubscriptions` have no caller. Harmless, deliberately kept, but it's unreachable surface
in a shipping binary. Fine to leave; worth knowing it's there.

## 5. The judgment

**The engineering is done.** Roadmap closed, four languages, both new features, 396 tests, a
verified Release build, a real icon, a hardened backend with versioned crypto and server-side
entitlements. The data-loss bug that started this — cloud sync that only pulled and corrupted
balances on every login — is long fixed.

**Three things stand between you and the App Store, and none of them are code:**

1. **Resolve the redesign.** Stash it or finish it. Do not build from a half-converted tree.
2. **Configure the deployment.** Two environment variables and a domain.
3. **Get a build onto a phone** — after 1 September for EAS, or via Xcode before then.

Nothing on that list requires me or the agent. That's the honest read: you have a finished product
and an unconfigured deployment, and you've had one for longer than the other.
